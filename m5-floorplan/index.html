Reading the topology

Why the memory PHYs hug the edges. The DRAM interface is the chip's widest off-die bus, and the LPDDR5X packages sit right beside the die. Putting the PHYs on the long edges keeps those traces short. The memory controllers and SLC slices sit just inside, so a request from any agent crosses the fabric, meets its SLC slice, and only then goes out through the PHY behind it.

128 bit ÷ 8 × 9,600 MT/s = 153.6 GB/s
drawn as 8 × 16-bit channels, 4 per edge

What changed from M4. The structural move is inside each GPU core: a dedicated matrix unit, Apple's Neural Accelerator, beside the shader ALUs. That is where the claimed fourfold rise in peak GPU AI compute comes from. Transformer-style matrix work now lives on the GPU, and the Neural Engine is kept for low-power, fixed-function inference.

M5 Pro and M5 Max are a different topology. They use Apple's Fusion Architecture, bonding two 3 nm dies into one SoC over a high-bandwidth interconnect, so this single-die map does not scale to them directly. For the whole M-series side by side, see the Apple silicon atlas.

Sources

Apple publishes block counts and bandwidth, not floorplans, and I could not find an annotated M5 die photograph in public. Core counts, caches, clocks, memory and GPU features below are sourced; the placement of blocks is my reconstruction from Apple's layout lineage, and the small system blocks (ISP, Secure Enclave, always-on processor, power management) are drawn where they usually sit. Relative areas are illustrative and were not measured.
